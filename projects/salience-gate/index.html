Building a Salience Gate for Voice Agents

A small-talk filter that sits between STT and the LLM in a voice agent, built through eleven measured experiment tracks, one honest negative result, and a final model that never trades away recall for speed

Every turn of a voice conversation carries real content and filler in the same breath. “Yeah, thanks, hold on, can you also check the second one” is one utterance with one task buried in three throwaway words. Sending all of it to the LLM every turn costs tokens and latency on the parts that don’t matter. The obvious fix, asking the LLM itself to ignore the filler, defeats the point, since you’d be paying LLM-scale latency on the exact turns you’re trying to make cheap. So I built a small, fast classifier that sits between speech-to-text and the LLM, scores each utterance for whether it’s actually task-relevant, and drops what isn’t, before the LLM ever sees it.

The repo isn’t public, so here’s the layout of the files this case study refers to:

The rule that shaped every decision

The failure mode that matters here isn’t symmetric. Dropping real task content breaks the agent. Missing a piece of chitchat costs nothing. So the whole project runs on one non-negotiable rule: never trade recall away for a better drop rate. Every experiment gets scored on false-drop rate first, the fraction of real task content that got wrongly dropped, and only after that on how much chitchat it actually removes. Early tracks held that floor at a recall of 0.975. The final model’s own threshold search used 0.95 and landed comfortably above it, at 0.951 measured recall on held-out data. The number moved, the rule didn’t.

The other piece of discipline was keeping two separate test sets and never letting one contaminate the other. A frozen benchmark, built from two public datasets, one for intent classification and one for mixed task-and-chitchat dialogue. And a second, independent holdout, seventy sentences generated by a fresh model instance with none of my session context and no phrasing borrowed from either dataset, the honest test for whether a gate generalizes past what it was tuned on.

Eleven tracks, and the one that went backward

# Approach Result
1 MiniLM embedding + logistic head shipped as the baseline
2 Contrastive fine-tune + per-intent OOD detector cracked the strict accuracy goal
3 Production hardening (context override, noise eval, confidence tiers) shipped as a layer on top
4 Noise-trained gate (ASR-error augmented) held recall under mishearing
5 POC web app (visible filtering, model picker) shipped, live demo
6 Independent holdout eval exposed the gates didn't generalize
7 Retrained on 76k more diverse chitchat made held-out performance worse
8 Cross-encoder, reads scope and utterance together fixed what track 7 couldn't
9 Energy-based out-of-distribution detection best open-world chitchat detection so far
10 Real syntactic clause segmentation partial win, model-dependent
11 Broader task-domain manifold for the OOD detector fixed false-drops on novel task types

Track 6 is the hinge. Every gate up to that point looked strong on the frozen benchmark. Run against the independent holdout, all of them missed casual asides with no benchmark-style phrasing, “I know this sounds dumb but I always forget,” scored 0.94 task-relevant by a gate that should have dropped it. That’s a real generalization gap, not a tuning problem.

Track 7 was the obvious next move: feed the model more chitchat. Seventy-six thousand more examples, pulled from two dialogue datasets, a full retrain. In-distribution numbers improved. Independent holdout performance got worse, chitchat correctly dropped fell from six out of fourteen to three out of fourteen. Fine-tuning on specific chitchat styles had pulled casual, open-ended phrasing inside the model’s idea of “in-domain,” which is the opposite of what I wanted. More supervised data of the same kind isn’t a fix for a generalization problem, it’s a way to overfit to whatever styles happen to be in the new data. I’d rather report that plainly than skip past the track that didn’t work.

The real fix was architectural. Track 8 swapped the bi-encoder for a cross-encoder that reads the assistant’s task scope and the user’s utterance together in one pass, instead of embedding them separately and comparing vectors. That single change is what closed the gap on mixed turns, holdout task-keep going from .857 to a perfect 1.0, and it’s the architecture the final production model builds on.

Getting the final model to actually work

The gate needs a decision that generalizes past canned phrasing, and an LLM is good at exactly that kind of judgment, at 100 to 1000 times the latency budget I have per utterance. So the plan was distillation: have an LLM label a large set of realistic (conversation context, utterance) pairs as keep or drop, then train a small, fast model on those labels instead of calling the LLM live.

The first two attempts at that badly underperformed. One locally, one on a first GPU training run, both landed around 7% chitchat dropped and roughly 200 milliseconds per utterance, nowhere close to useful. I don’t have a confirmed root cause for that specific jump and I’d rather say so than guess at one for a public case study. A fuller training run on the complete labeled set fixed both numbers at once: 100% task-recall, 92.9% chitchat dropped, 12.7 milliseconds per utterance, comfortably inside the recall floor. That’s the model that shipped. A smaller variant traded some accuracy on answer-type utterances for a 4-millisecond inference time, a real tradeoff if latency ever gets tighter than accuracy.

The production layer around all of this, from track 3, is what actually made the gate usable turn to turn rather than just accurate in isolation. If the agent just asked a question, every reply gets kept automatically, since “yes, that’s right” scores as chitchat on its own but is exactly the information the agent needs. Dropped content stays in memory instead of vanishing, since a later “what did I say about the second one” needs to resolve against something the LLM never directly saw. And utterances that land in an uncertain confidence band get escalated to a tier instead of a hard keep-or-drop call.

The demo

The POC app makes the filtering visible instead of theoretical. Talk to it, and it shows every span of your utterance as kept or dropped in real time, green for kept, struck through for dropped, with a confidence score on hover. A model picker swaps between six of the shipped gates live, so you can watch the same sentence get scored differently by the baseline, the cross-encoder, and the rest. Token counters track what actually got sent to the LLM against what would have been sent with no gate at all, and a toggle lets you turn filtering off entirely for a direct side-by-side.

Where this stands, and what’s still unsolved

This ran fast, June 12 through June 18, twenty-four commits carrying eleven experiment tracks, a production hardening layer, a live demo app, and a full distillation push, not a long-running system. I’d rather be upfront about the compressed timeline than imply otherwise.

What’s not solved: purely reflective chitchat, the kind with no clear topic and no clear filler either, “I know this sounds dumb but I always forget,” still scores task-relevant even on the best gate. That’s a real, open gap, not a rounding error I’m smoothing over. The honest generalization test this whole project was built around is also the test that shows exactly where the current approach still falls short, which feels like the right note to end a case study about a recall floor on.
